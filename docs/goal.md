# `/goal` 持续目标循环

`/goal` 用于需要 agent 持续工作、反复验证和修复，直到满足明确完成条件的任务。它与普通对话不同：创建目标后，agent 会自动进入下一轮，不需要用户逐轮发送“继续”。

适合使用 `/goal` 的任务：

- 修复一组测试，直到测试命令通过
- 完成一个可由构建、lint、测试或脚本检查的功能
- 生成文件，并验证文件内容或项目状态
- 需要多轮调查、实现、验证和修复的工程任务

主观问题、开放式讨论或没有可验证完成条件的任务应使用普通对话。没有验证器或用户确认的 goal 无法完成，会停止为 `blocked`，避免无限循环。

## 快速开始

```text
/goal 修复所有单元测试 --verify "pnpm test" --max-turns 10 --token-budget 100000
```

agent 会持续工作，并在认为目标完成时运行 `pnpm test`。验证失败会把结果送回下一轮继续修复；验证通过后目标才会变成 `complete`。

默认最多运行 20 个外层 goal turn。未指定 `--token-budget` 时不设置 goal 级 token 上限。

## 创建目标

```text
/goal <目标> [选项]
```

| 选项                         | 作用                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| `--verify "<命令>"`          | 使用 shell 命令验证；退出码为 0 表示通过                    |
| `--verifier-agent <名称>`    | 使用只读子 agent 独立检查完成情况；推荐内置 `goal-verifier` |
| `--verifier-prompt "<要求>"` | 指定子 agent 的检查标准，可放在对应 `--verifier-agent` 前后 |
| `--confirm`                  | 完成前要求用户明确确认                                      |
| `--max-turns <n>`            | 设置最多外层循环次数，默认 20                               |
| `--token-budget <n>`         | 设置该目标从创建起可消耗的总 token 上限                     |

选项可以组合。多个验证器按命令中出现的顺序运行，任一失败即停止本次验证；配置 `--confirm` 时，所有验证器通过后还需要用户确认。

### shell 验证器

```text
/goal 实现配置加载功能 --verify "pnpm typecheck" --verify "pnpm test packages/core/tests/config.test.ts" --max-turns 12
```

shell 验证器在当前工作目录运行，默认超时 120 秒，并遵循正常的 shell 权限策略。命令包含空格时必须使用引号包裹；命令内的引号按当前终端和 `/goal` 参数解析规则转义。

### 子 agent 验证器

```text
/goal 修复登录流程的安全问题 --verifier-agent goal-verifier --verifier-prompt "只读检查改动、测试和权限边界，确认问题已完整修复" --max-turns 10
```

`goal-verifier` 是内置只读验证 agent。它会检查目标、仓库状态、改动和验证证据，并返回结构化结论，不会修改文件。子 agent 验证更适合无法只用单条命令判断、但仍有清晰验收标准的任务。

### 用户确认

```text
/goal 整理这组错误日志并给出根因报告 --confirm --max-turns 6
```

当自动检查不足以判断质量时，可以使用 `--confirm`。agent 请求完成后会弹出确认；选择 `No` 会继续工作，选择 `Yes` 才会完成。`--confirm` 可以单独使用，也可以作为自动验证器之后的最后一道门禁。

## 控制运行中的目标

| 命令                          | 作用                                                   |
| ----------------------------- | ------------------------------------------------------ |
| `/goal` 或 `/goal status`     | 查看目标、状态、轮次、token 预算和最近验证结果         |
| `/goal pause`                 | 暂停活动目标；运行或权限确认期间也可输入               |
| `/goal resume`                | 恢复 `paused`、`blocked` 或 `max_turns` 状态的目标     |
| `/goal resume --max-turns +3` | 增加 3 轮上限后恢复；也可传绝对值，如 `--max-turns 12` |
| `/goal steer <指令>`          | 给下一轮追加人工指导，并继续当前目标                   |
| `/goal edit <新目标>`         | 修改当前目标描述                                       |
| `/goal edit --max-turns <n>`  | 修改最大轮数                                           |
| `/goal verify`                | 立即运行已配置的验证；失败时继续修复                   |
| `/goal cancel`                | 取消目标，不再自动运行                                 |
| `/goal clear`                 | 删除当前 goal 状态，以便创建新目标                     |

`pause`、`cancel` 和 `clear` 会中断正在进行的 goal 工作并释放待处理的交互。按 `Esc` 中断活动 goal 时，目标会暂停，可稍后用 `/goal resume` 继续。

## 状态与停止条件

| 状态             | 含义                                                 |
| ---------------- | ---------------------------------------------------- |
| `active`         | 正在自动执行                                         |
| `paused`         | 被用户暂停，可恢复                                   |
| `blocked`        | 缺少验证器，或同一外部阻塞重复出现；补充条件后可恢复 |
| `complete`       | 所有验证步骤和可选用户确认均已通过                   |
| `max_turns`      | 达到最大轮数；会生成当前进展摘要，可增加轮数后恢复   |
| `budget_limited` | 达到 goal token 预算                                 |
| `usage_limited`  | 达到供应商或账户用量限制                             |
| `cancelled`      | 被用户取消                                           |
| `failed`         | 发生不可恢复错误                                     |

系统还会在同一个外部阻塞连续出现三次时停止为 `blocked`，并在达到轮数或 token 上限时停止。这些门禁保证 `/goal` 不会无界运行。

## 使用建议

- 把“完成什么”和“怎样算完成”分别写清楚。目标描述负责范围，验证器负责验收。
- 优先使用确定性的测试、构建或检查脚本；需要语义判断时再增加 `goal-verifier`。
- shell 验证器应检查结果，不应顺带修改项目，否则验证过程本身会改变被验证状态。
- 为成本和异常情况设置合理的 `--max-turns`，长任务再增加 `--token-budget`。
- `/goal` 状态会随会话保存。恢复历史会话后，可先运行 `/goal status` 检查，再决定是否 `/goal resume`。
