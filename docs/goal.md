# `/goal` 持续目标循环

`/goal` 用于需要 agent 持续工作、反复验证和修复，直到满足明确完成条件的任务。它与普通对话不同：创建目标后，agent 会自动进入下一轮，不需要用户逐轮发送“继续”。

适合使用 `/goal` 的任务：

- 修复一组测试，直到测试命令通过
- 完成一个可由构建、lint、测试或脚本检查的功能
- 生成文件，并验证文件内容或项目状态
- 需要多轮调查、实现、验证和修复的工程任务

主观问题和开放式讨论通常更适合普通对话。用户不必手写验证器：未指定验证选项时，内置只读 `goal-verifier` 会从自然语言目标、引用资料、项目规则和当前仓库状态中推导完成要求并独立验收。

## 快速开始

```text
/goal 修复当前项目所有测试失败，直到测试成功为止
```

agent 会先根据目标和项目结构确定完整测试入口并持续修复。它请求完成时，内置 `goal-verifier` 会重新推导全部要求、检查当前证据；验证失败会把 findings 和 required fixes 送回下一轮继续修复，验证通过后目标才会变成 `complete`。

未指定 `--max-turns` 和 `--token-budget` 时，两者都不设上限。需要控制成本或运行时间时再显式设置。

## 创建目标

```text
/goal <目标> [选项]
```

| 选项                         | 作用                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| `--verify "<命令>"`          | 使用 shell 命令验证；退出码为 0 表示通过                    |
| `--verifier-agent <名称>`    | 使用只读子 agent 独立检查完成情况；推荐内置 `goal-verifier` |
| `--verifier-prompt "<要求>"` | 指定子 agent 的检查标准，可放在对应 `--verifier-agent` 前后 |
| `--confirm`                  | 完成前要求用户明确确认                                      |
| `--max-turns <n>`            | 设置最多外层循环次数；默认不限制                            |
| `--token-budget <n>`         | 设置该目标从创建起可消耗的总 token 上限                     |

选项可以组合。多个显式验证器按命令中出现的顺序运行，任一失败即停止本次验证；它们全部通过后，系统仍运行内置 `goal-verifier` 检查显式命令是否覆盖完整目标。配置 `--confirm` 时，所有自动检查通过后还需要用户确认。

### shell 验证器

```text
/goal 实现配置加载功能 --verify "pnpm typecheck" --verify "pnpm test packages/core/tests/config.test.ts" --max-turns 12
```

shell 验证器在当前工作目录运行，默认超时 120 秒，并遵循正常的 shell 权限策略。命令包含空格时必须使用引号包裹；命令内的引号按当前终端和 `/goal` 参数解析规则转义。

### 子 agent 验证器

```text
/goal 修复登录流程的安全问题 --verifier-agent goal-verifier --verifier-prompt "只读检查改动、测试和权限边界，确认问题已完整修复" --max-turns 10
```

`goal-verifier` 是内置只读验证 agent，并且每个 goal 都会自动运行。它会独立从原始目标、引用资料、项目规则和当前状态推导要求，逐项检查证据并返回结构化 findings/required fixes，不会修改文件。`--verifier-agent` 用于额外增加定制检查，不是基本必填项。

### 用户确认

```text
/goal 整理这组错误日志并给出根因报告 --confirm --max-turns 6
```

当自动检查不足以判断主观质量时，可以使用 `--confirm`。语义 verifier 会先检查所有具备客观证据的要求，但把最终主观认可留给后续确认；选择 `No` 会继续工作，选择 `Yes` 才会完成。

## 控制运行中的目标

| 命令                          | 作用                                                  |
| ----------------------------- | ----------------------------------------------------- |
| `/goal` 或 `/goal status`     | 查看目标、状态、轮次、token 预算和最近验证结果        |
| `/goal pause`                 | 暂停活动目标；运行或权限确认期间也可输入              |
| `/goal resume`                | 恢复 `paused`、`blocked` 或 `max_turns` 状态的目标    |
| `/goal resume --max-turns +3` | 为已有显式上限增加 3 轮；无限 goal 请用绝对值设置上限 |
| `/goal steer <指令>`          | 给下一轮追加人工指导，并继续当前目标                  |
| `/goal edit <新目标>`         | 修改当前目标描述                                      |
| `/goal edit --max-turns <n>`  | 修改最大轮数                                          |
| `/goal verify`                | 立即运行已配置的验证；失败时继续修复                  |
| `/goal cancel`                | 取消目标，不再自动运行                                |
| `/goal clear`                 | 删除当前 goal 状态，以便创建新目标                    |

`/goal status` 只读取状态，不会启动新任务，也不会暂停已经在后台执行的 goal。若状态是 `active`，查询后仍可能看到正在进行的 verifier 或下一轮修复输出；希望查看后停止时，先用 `/goal pause`。`pause`、`cancel` 和 `clear` 会中断正在进行的 goal 工作并释放待处理的交互。按 `Esc` 中断活动 goal 时，目标会暂停，可稍后用 `/goal resume` 继续。

## 状态与停止条件

| 状态             | 含义                                                 |
| ---------------- | ---------------------------------------------------- |
| `active`         | 正在自动执行                                         |
| `paused`         | 被用户暂停，可恢复                                   |
| `blocked`        | 同一外部阻塞重复出现；外部条件变化或人工指导后可恢复 |
| `complete`       | 所有验证步骤和可选用户确认均已通过                   |
| `max_turns`      | 达到最大轮数；会生成当前进展摘要，可增加轮数后恢复   |
| `budget_limited` | 达到 goal token 预算                                 |
| `usage_limited`  | 达到供应商或账户用量限制                             |
| `cancelled`      | 被用户取消                                           |
| `failed`         | 发生不可恢复错误                                     |

系统会在同一个外部阻塞连续出现三次时停止为 `blocked`，并在达到用户显式设置的轮数或 token 上限时停止。重复的 verifier failure 会触发逐级策略纠偏，但不会自动降低验收标准；用户随时可以 pause、cancel 或按 Esc 中断默认无限的 goal。

## 使用建议

- 直接用自然语言写清目标、范围和禁止事项；系统会自动推导验收要求。
- 确定性的测试、构建或检查脚本可以作为附加证据，但不能替代对完整目标的语义审计。
- shell 验证器应检查结果，不应顺带修改项目，否则验证过程本身会改变被验证状态。
- 需要控制成本时设置 `--max-turns` 或 `--token-budget`；不设置就是无限。
- `/goal` 状态会随会话保存。恢复历史会话后，可先运行 `/goal status` 检查，再决定是否 `/goal resume`。
